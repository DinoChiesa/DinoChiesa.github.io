How Token Protection Works

  1. Pre-Flight reCAPTCHA: Before submitting the OAuth grant request, grecaptcha.execute() obtains a verification token for the token action.
  2. Protected Token Endpoint: The client sends an HTTP POST to https://therealdinochiesa2-eval-test.apigee.net/oauth2-cc-recaptcha/token with grant_type=client_credentials, HTTP Basic authentication, and the recaptcha-token header.
  3. Apigee Policy Enforcement: Apigee verifies the reCAPTCHA token against Google. If the score meets the minimum threshold (e.g. ≥ 0.5), it proceeds to validate client credentials and mint the access token. If below threshold, Apigee rejects the request with an HTTP 403 Forbidden.
  4. Credential Harvesting Mitigation: This prevents attackers who find or steal client credentials from launching automated brute-force scripts to harvest access tokens.
